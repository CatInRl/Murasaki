# Murasaki 0.8.0 — 统一全局搜索条 + Tab 栏工作区归属 Spec

## Problem Statement

当前搜索能力割裂：

- find-in-files 底部面板（Ctrl+Shift+F）仅做工作区内 `.md` 内容搜索，无法快速按文件名找文件、切换到已打开标签、打开最近文件。
- 打开文件 / 切换标签没有统一的快速入口（依赖文件树 / 标签栏点击），`Ctrl+P` 无绑定。
- 面板形态偏"工具"而非"导航"：结果堆在底部，无分组、无键盘导航、无打开即走。

用户期望：一条快捷键拉起的**统一全局搜索条**，输入关键字混合返回「打开的标签 + 最近文件 + 文件名 + 内容命中（仅 .md）」，回车即打开文件 / 切换标签，**取代 find-in-files 底部面板**。

Tab 栏同样存在信息割裂：打开工作区外文件、另存为到工作区外、切换工作区后残留的旧 tab，外观上与工作区内文件无差别，用户容易误以为它们属于当前工作区。

用户期望：tab 栏能**一眼区分工作区内 / 工作区外**的文件，且不打扰（不持久化、不改变 tab 顺序）。

## Solution

顶部居中浮动的统一搜索条（Murasaki 主题）：

- **快捷键**：`Ctrl+P` 为主入口；`Ctrl+Shift+F`（原 find-in-files）也映射到统一条。原生菜单「在文件中查找…」打开统一条。
- **混合结果**：打开的文件、最近文件、工作区文件名、内容命中（仅 `.md`）四类按组展示。
- **前端模糊匹配**：文件名 / 标签 / 最近走前端匹配（字符跳序 + 大小写不敏感 + 多词 AND）。
- **内容命中**：复用 Rust `search_workspace`（仅 `.md`，含行号 + 片段），支持正则 / 大小写 / 全词选项。
- **打开**：回车复用 `useFileActions.openFile`（无工作区时自动以文件所在目录建工作区），标签已打开则切换到该标签。
- **下线**：删除 `SearchPanel.vue`，`find-in-files` 命令重指向统一条。

### 交互

- 快捷键拉起，输入框自动聚焦；`Esc` 关闭并还原焦点。
- `↑` / `↓` 选择条目，`⏎` 打开 / 切换，`Tab` 在结果与高级选项间循环。
- 匹配文本紫色高亮（`rgba(147, 51, 234, 0.2)`，对齐 `SearchPanel` 既有 `.match-highlight`）。
- 高级选项（正则 / 大小写 / 全词）经 sliders 图标展开，仅作用于内容命中。
- footer 显示操作提示 + 结果计数；结果达到上限时显示截断提示。
- 空查询默认态仅显示「打开的标签 + 最近文件」。

### 结果分组与排序（W2 决策）

| 分组 | 数据源 | 数量上限 | 排序 |
|---|---|---|---|
| 打开的标签 | `tabsStore.tabs` | 5 | 标签打开顺序 |
| 最近文件 | `persistence.recentEntries` | 5 | 最近时间倒序（排除已在标签中） |
| 文件名 | `workspaceStore.fileTree` 遍历 | 8 | 前缀命中优先 → 文件名长度升序 |
| 内容命中 | Rust `search_workspace`（仅 `.md`） | 5 文件 × 每文件 2 条 | 行号升序 |

- 空查询默认态：仅显示「打开的标签 + 最近文件」。
- 无工作区降级：仅「打开的标签 + 最近文件」，仍可搜索切换 / 打开。
- 去重：同一路径不跨组重复（优先级 标签 > 最近 > 文件名 > 内容，前面已出现则后面跳过）。

### 模糊匹配语义

- **字符跳序**：query 的字符在目标文本中按序出现即命中（大小写不敏感）。
- **多词 AND**：query 按空白拆词，每个词都需命中。
- **高亮**：返回每个匹配词的 ranges（在标题 / 片段内的起止位置）。
- **前缀优先**：文件名以首词开头命中时排前。

### 架构边界（W3 决策）

- 新增命令 `global-search`（默认 `Ctrl+P`）；`find-in-files` 命令 handler 重指向统一条（保留其 `Ctrl+Shift+F` 绑定）。
- 前端：`GlobalSearchBar.vue`（新组件）+ `matchText` / `buildGroups`（纯函数，便于单测）。
- Store：`useSearchStore` 改造 —— 保留 `search_workspace` 复用（内容命中）；`visible` 改为控制统一条；文件名 / 标签 / 最近不再走 Rust。
- 打开：复用 `useFileActions.openFile`（内部已处理 `addRecent` + 无工作区自动开工作区）。
- 删除 `SearchPanel.vue` 及其在 `App.vue` 的挂载、相关样式与事件。

### Tab 栏工作区归属（方案 B：单角标）

tab 栏区分工作区内 / 工作区外文件，采用**单角标**方案（不分组、不改变顺序）：

- **工作区外角标 (Out-of-workspace Marker)**：工作区外标签页的通用文件图标替换为前导 ↗ 图标，激活时随主题变紫（与文件图标激活态一致）。
- **工作区内标签页**：保持通用文件图标不变。
- **未保存标签页**：`path === null`，不属于"工作区外"，不显示角标。
- **工作区归属 (Workspace Affiliation)**：派生布尔属性，由 `workspacePath` 与 `tab.path` 实时计算（路径前缀 + 目录边界 + Windows 大小写不敏感），不持久化，不改变 tab 顺序。

## User Stories

### 议题簇 0：快捷键与入口

1. 作为用户，我按 `Ctrl+P` 能拉起统一搜索条，输入框自动聚焦，`Esc` 关闭。
2. 作为用户，我按 `Ctrl+Shift+F` 也拉起统一搜索条（取代原 find-in-files 面板），行为一致。
3. 作为用户，我从原生菜单「在文件中查找…」能打开统一搜索条。
4. 作为用户，我在「设置 → 快捷键」中能看到「全局搜索」条目并可自定义绑定。

### 议题簇 1：匹配与分组

5. 作为用户，我输入关键字后结果按「打开的标签 > 最近文件 > 文件名 > 内容命中」分组展示，组标题清晰。
6. 作为用户，我刚拉起搜索条（空查询）时只看到「打开的标签 + 最近文件」，便于快速导航。
7. 作为用户，我在没有打开工作区时搜索，仍能搜索并打开最近文件 / 切换标签。
8. 作为用户，我看到匹配文本被紫色高亮；文件名前缀命中排在该组前面。
9. 作为用户，我看到内容命中仅来自 `.md` 文件，展示行号 + 片段，每文件最多 2 条，避免刷屏。

### 议题簇 2：数据流

10. 作为用户，我回车打开一个未打开的文件，文件在标签中打开并选中。
11. 作为用户，我回车选择已打开的标签条目，应用切换到该标签，不重复打开。
12. 作为用户，我看到同一路径不跨组重复出现（已在标签中的文件不会同时出现在最近 / 文件名 / 内容组）。
13. 作为用户，我开启正则 / 大小写 / 全词选项后，内容命中按选项过滤。

### 议题簇 3：UI

14. 作为用户，我看到的搜索条是顶部居中浮动，聚焦态 / 空态 / 加载态 / 截断态齐全，风格与 Murasaki 主题一致。
15. 作为用户，我可以用 `↑` / `↓` 选择、`⏎` 打开、`Esc` 关闭，键盘全程可用。
16. 作为用户，我看到 Markdown 文件带紫色 M 徽标，已打开条目带「已打开」chip。

### 议题簇 4：测试

17. 作为开发者，模糊匹配与分组排序逻辑有纯函数单测覆盖（跳序 / 多词 AND / 前缀优先 / 去重 / 无工作区降级）。
18. 作为开发者，端到端测试覆盖「快捷键拉起 → 输入 → 回车打开」主链路。

### 议题簇 5：Tab 栏工作区归属

19. 作为用户，我能在 tab 栏一眼区分工作区内 / 工作区外的文件（工作区外显示 ↗ 角标）。
20. 作为用户，工作区外标签页激活时角标随主题变紫，与文件图标激活态视觉一致。
21. 作为用户，未保存（无路径）标签页不显示角标，不误导。
22. 作为用户，切换工作区后残留的旧 tab 自动变为工作区外展示，无需手动处理。

## Implementation Decisions

### 议题簇 0：快捷键与入口

- `shortcutRegistry.ts` 新增命令 `{ id: "global-search", labelKey: "settings.shortcuts.globalSearch", category: "file", defaultShortcut: "Ctrl+P", scope: "global" }`。
- `find-in-files` 命令保留（`Ctrl+Shift+F`），其 handler 从 `searchStore.visible = true`（旧面板）改为打开统一搜索条；菜单文案可保留「在文件中查找…」或改为「全局搜索…」。
- `useCommands.ts` 增加 `case "global-search"`，与 `find-in-files` 共用打开统一搜索条的逻辑。
- `menu.rs`：Edit 菜单 `find-in-files` 项不变（打开统一条）；如新增菜单项则与命令 ID 一致。
- i18n：`settings.json`（zh/en）增加 `settings.shortcuts.globalSearch` 文案「全局搜索 / Global Search」。

### 议题簇 1：匹配与分组

- 新增纯函数 `matchText(text, query)` → `{ ok, ranges }`：字符跳序匹配，大小写不敏感，多词 AND，返回每个命中词的 ranges。
- 新增纯函数 `buildGroups(ctx)` → `Group[]`：按 标签 > 最近 > 文件名 > 内容 分组，实现数量上限、去重、前缀优先排序、无工作区降级与空查询默认态。
- 输入防抖触发内容命中（复用 `search_workspace`）；文件名 / 标签 / 最近同步前端过滤。

### 议题簇 2：数据流

- `useSearchStore` 保留 `search_workspace` 调用与进度事件，`visible` 语义改为「统一搜索条开关」；文件名匹配不再依赖 Rust `filename_results`。
- 内容命中取消改为在切换 query / 关闭搜索条时执行。
- 打开统一调用 `useFileActions.openFile`；对「已打开标签」条目直接切换 `tabsStore` 激活 tab，不重复 openFile。

### 议题簇 3：UI

- 新增 `GlobalSearchBar.vue`，复用 Murasaki 主题变量（`--murasaki-*`）、`md-badge` 徽标、`SearchPanel` 的高亮与分组样式，参考 `.scratch/wayfinder/prototype-unified-search.html` 高保真原型。
- 挂载于 `App.vue` 顶层（teleport 或根节点），`v-if="searchStore.visible"`。
- 键盘导航：输入框 `keydown` 处理 `↑/↓/⏎/Esc/Tab`；选中项滚动进视区。
- 高级选项复用 `SearchPanel` 既有选项（regex / caseSensitive / wholeWord）。

### 议题簇 4：测试

- `matchText` / `buildGroups` 纯函数单测：跳序、多词 AND、前缀优先、去重、空查询默认态、无工作区降级、数量上限。
- 快捷键单测：`global-search`（Ctrl+P）与 `find-in-files`（Ctrl+Shift+F）均打开统一条。
- E2E：`e2e/specs/global-search.spec.ts` 覆盖「快捷键拉起 → 输入 → 回车打开」。

### 议题簇 5：Tab 栏工作区归属

- `path.ts` 新增 `isPathUnder(base, target)`：判定 `target` 是否位于 `base` 目录之下（路径前缀 + 目录边界 + Windows 大小写不敏感），纯函数便于单测。
- `TabBar.vue`：对每个 `tab.path !== null` 的 tab 计算 `isOutOfWorkspace = !isPathUnder(workspacePath, tab.path)`；工作区外 tab 用 `ArrowUpRight`（lucide）角标替换通用文件图标，激活态随主题变紫。
- 未保存 tab（`path === null`）不显示角标；无工作区时所有有路径 tab 视为工作区外。
- tooltip：工作区外 tab 的 `title` 前加「工作区外：」前缀。
- i18n：`editor.tabBar` 增加工作区外前缀文案（zh/en）。

## Non-Goals

- 编辑器内 `Ctrl+F` 查找 / 替换保持现状（CM6 自带，不并入统一条）。
- 非 Markdown 文件的内容搜索（已确认仅 `.md`）。
- 全库全文索引 / ripgrep 级性能优化。
- 拼音匹配 / 编辑距离打分（模糊匹配仅字符跳序 + 多词 AND）。
- 历史搜索记录 / 搜索历史记忆。
- 自定义快捷键能力（issue #110 已 deferred；`global-search` 走既有快捷键自定义体系）。
- Tab 栏不按工作区内外分组 / 排序（方案 B 仅角标区分）。
