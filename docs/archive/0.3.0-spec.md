# Murasaki 0.3.0 — 整体 UX 对齐 + WYSIWYG 模式 Spec

## Problem Statement

0.2.0 版本完成了核心编辑器、文件管理、Agent 功能的基础实现，但 UX 层面存在系统性问题：

- **设计系统未落地**：`murasaki-ui-design/` 定义了完整的紫色 token 化体系（`--murasaki-*` + lucide 图标 + 语义类回退），但实现侧从未准确落地——36 处原生 `alert()/confirm()/prompt()`、emoji 替代图标、硬编码颜色散布各处、naive-ui 默认样式未对齐 token。
- **反馈系统基础设施缺失**：无吐司系统、无统一对话框、右键菜单覆盖不足（TabBar/Editor/Agent 消息右键全无）、空态/错误态/加载态用 naive-ui 默认样式与设计规范差距大。
- **编辑模式单一**：仅支持分屏模式，用户在写复杂 markdown 语法（代码块/表格）时预览区分散注意力，且无法获得"像 Typora 一样所见即所得"的写作体验。
- **设置界面陈旧**：720px 模态弹窗 + 即时持久化模型 + 4 个分类，与参考设计的"独立窗口 + 显式 Save + 3 个分类"差距大，且设置项扩充后模态会拥挤。
- **Agent 面板 UX 粗糙**：大量 emoji 替代图标、工具调用状态栏简陋、无提案列表卡片、无用户/助手消息气泡区分、无 provider chip。

用户需要一个**视觉一致、交互流畅、模式可切换、配置可掌控**的 markdown 编辑器，而非"功能能用但 UX 粗糙"的原型。

## Solution

0.3.0 进行**整体 UX 对齐 + WYSIWYG 模式实现**，分 8 个议题簇：

1. **设计系统基础对齐**：引入 lucide-vue-next 统一图标库；保留 naive-ui 但通过 themeOverrides 对齐 `--murasaki-*` token；不引入 Tailwind 保留 scoped CSS；补全字号/阴影/menubar-height/transition token。
2. **布局骨架**：保留 Tauri 原生菜单栏（不实现 in-app menu bar）；标签栏移除主题选择器污染；状态栏按 ux-panels 规范补全已保存指示/孤立会话清理/provider chip。
3. **反馈系统**：自建吐司 store + Teleport 容器（6 变体）；自建对话框 store + Promise API（alert/confirm/prompt/conflict 四类型，替换 36 处原生弹窗）；自建右键菜单 store + 数据驱动（4 处右键菜单）。
4. **状态展示**：自建 EmptyState + ErrorState + Skeleton 三兄弟，共享虚线边框容器与 props 模式，替换 naive-ui NEmpty/NSpin/NSkeleton。
5. **面板与侧栏视觉**：Agent 面板全量视觉对齐（emoji→lucide + 工具调用折叠卡片 + 提案列表卡片 + 用户/助手气泡 + provider chip）；文件树选中态补 text-primary；搜索高亮改紫色 20%。
6. **浮层与工具栏**：浮层用 NPopover + themeOverrides；WYSIWYG 工具栏 0.3.0 实现（源码/WYSIWYG 双模式共用，按钮行为一致）。
7. **WYSIWYG 模式**：采用 CodeMirror 6 内 WYSIWYG（Typora 路线），单编辑器实例，markdown 文本为唯一数据源，通过 ViewPlugin + Decoration 隐藏语法标记。三种模式（source/split/wysiwyg）共用同一 CM6 实例，全部运行时切换。P0+P1 功能全做，P2/P3 遗留。
8. **设置界面**：改为 Tauri 多窗口形态；3 个分类（常规/编辑器/AI）；显式 Save 模型；AI 分类含 Provider 列表 + 测试连接 + 高级参数折叠区。

## User Stories

### 议题簇 0：设计系统基础

1. 作为一名用户，我希望应用内的图标视觉统一且清晰可辨，这样我不会看到 emoji 与 SVG 混用的粗糙感。
2. 作为一名用户，我希望在浅色/深色模式下所有组件的颜色都一致变化，这样不会出现某个组件在深色模式下白底刺眼。
3. 作为一名开发者，我希望颜色/圆角/阴影都有明确的 token 变量，这样我不需要在组件里硬编码十六进制色值。
4. 作为一名用户，我希望字号在不同组件间保持一致（如所有次要文字都是 13px），这样视觉层级清晰。

### 议题簇 1：布局骨架

5. 作为一名用户，我希望标签栏只显示标签和新建按钮，不被主题选择器等其他控件污染，这样我能专注于文件切换。
6. 作为一名用户，我希望状态栏能显示"已保存"指示、当前 AI provider、孤立会话清理提示，这样我能掌握应用状态。
7. 作为一名用户，我希望通过 OS 原生菜单栏（而非应用内菜单条）访问文件/编辑/段落/主题/帮助菜单，这样我能用 Alt+F 等系统快捷键操作。

### 议题簇 2：反馈系统

8. 作为一名用户，我希望保存文件后看到右上角弹出一个短暂的"已保存"提示，这样我能确认操作成功。
9. 作为一名用户，我希望删除文件后看到一个带"撤销"按钮的吐司，这样我能在 10 秒内反悔。
10. 作为一名用户，我希望导出 HTML 时看到一个带进度条的吐司，这样我能知道导出进度。
11. 作为一名用户，我希望所有确认对话框都有统一的视觉（图标 + 标题 + 描述 + 取消在左/确认在右），这样不会看到原生 alert 的粗糙样式。
12. 作为一名用户，我希望在标签上右键能看到"关闭/关闭其他/关闭右侧/关闭左侧/关闭所有/复制路径/在文件资源管理器中显示"等操作，这样我能高效管理标签。
13. 作为一名用户，我希望在编辑器右键能看到"剪切/复制/粘贴/全选 + 查找替换/插入表格/插入链接/插入图片"等操作，这样无需记忆快捷键。
14. 作为一名用户，我希望在 Agent 消息上右键能"复制/复制 Markdown 源码/插入到编辑器/从当前消息重新生成"，这样我能复用 Agent 输出。
15. 作为一名用户，我希望文件树右键菜单项都有图标和快捷键提示，这样视觉一致且易于学习。

### 议题簇 3：状态展示

16. 作为一名用户，当文件树为空时，我希望看到一个虚线边框容器内的"打开一个文件夹开始"提示和"打开文件夹"按钮，而不是空白。
17. 作为一名用户，当搜索无结果时，我希望看到"未找到匹配的文件"提示和"清空搜索"按钮。
18. 作为一名用户，当文件加载失败时，我希望看到一个黄色警告图标的错误态和"重试"按钮，而不是一堆错误信息。
19. 作为一名用户，当文件树正在加载时，我希望看到骨架屏动画，而不是空白或旋转图标。

### 议题簇 4：面板与侧栏视觉

20. 作为一名用户，我希望 Agent 面板的工具调用以折叠卡片形式展示（"工具·{summary}" 点击展开），这样不会占用过多对话流空间。
21. 作为一名用户，我希望 Agent 面板有一个提案列表卡片，列出所有提案的文件名/行号/类型/接受拒绝状态，点击能跳转到编辑器对应位置并高亮闪烁。
22. 作为一名用户，我希望用户消息右对齐用紫色气泡、助手消息左对齐用无背景或浅灰背景，且各有 user/bot 图标，这样对话流易于阅读。
23. 作为一名用户，我希望 Agent 输入框上方显示当前 provider 的 chip（`sparkles` 图标 + provider 名），这样我知道在用哪个模型。
24. 作为一名用户，我希望 Agent 中断后看到 `alert-triangle` + "已中断" 文本，而不是 emoji ⚠。
25. 作为一名用户，我希望文件树选中项的文字变紫色且加粗，这样选中态更明显。
26. 作为一名用户，我希望搜索高亮用紫色 20% alpha 背景，而不是黄绿色，这样与应用品牌色一致。

### 议题簇 5：浮层与工具栏

27. 作为一名用户，我希望点击"插入链接"按钮弹出浮层表单填写 URL 和锚文本，这样无需手写 `[](url)` 语法。
28. 作为一名用户，我希望在 WYSIWYG 模式下看到顶部工具栏（粗体/斜体/标题/列表/插入等分组按钮），这样能像 Word 一样点按钮格式化。
29. 作为一名用户，我希望工具栏按钮在源码模式和 WYSIWYG 模式下都可用，行为一致（都是修改底层 markdown 文本）。

### 议题簇 6：欢迎页

30. 作为一名用户，我希望欢迎页底部显示常用快捷键提示（Ctrl+O 打开 / Ctrl+N 新建 / Ctrl+Shift+O 打开文件夹），这样我能快速学习操作。
31. 作为一名用户，我希望欢迎页的品牌用 lucide `book-open` 图标 + "Murasaki" 文字，而不是粗糙的内联 SVG 盒子。
32. 作为一名用户，当最近文件列表为空时，我希望看到 EmptyState 组件提示"暂无最近文件"，而不是空白。

### 议题簇 7：WYSIWYG 模式

33. 作为一名用户，我希望在设置中切换到"所见即所得"模式后，编辑器立即（无需重启）变成像 Typora 一样的渲染效果——输入 `**bold**` 立即变粗体且看不到 `**`。
34. 作为一名用户，我希望在 WYSIWYG 模式下光标进入某段时，该段的 markdown 语法标记重新显示为 dim 灰色，这样我能编辑语法；光标离开后标记再次隐藏。
35. 作为一名用户，我希望在 WYSIWYG 模式下能正常使用 Agent 功能——Agent 生成的提案直接在 WYSIWYG 编辑器中渲染（绿色 insert / 红色 strikethrough + 浮动 ✓/✗ 按钮），无需切换源码模式。
36. 作为一名用户，我希望在 WYSIWYG 模式下看到代码块、链接、图片、表格、数学公式、Mermaid 图表的实时渲染（块级 widget），而不是原始 markdown 语法。
37. 作为一名用户，我希望在三种模式（源码/分屏/所见即所得）之间运行时切换，无需重启应用。
38. 作为一名用户，我希望 Agent 面板在三种模式下都可见可用，不会因为切到 WYSIWYG 模式就消失。
39. 作为一名用户，我希望在 WYSIWYG 模式下用工具栏的 Bold 按钮能正确应用粗体（toggle `**` 标记并立即渲染粗体效果）。

### 议题簇 8：设置界面

40. 作为一名用户，我希望设置作为独立 OS 窗口打开（可独立最小化/关闭，主窗口不被遮挡），这样我能一边看主编辑器一边调设置。
41. 作为一名用户，我希望设置窗口有"恢复默认 / 保存"两个按钮，这样我能批量调整后一次性应用，且能恢复默认值。
42. 作为一名用户，我希望关闭未保存的设置窗口时弹出"保存/不保存/取消"确认，这样我不会误丢配置。
43. 作为一名用户，我希望设置分 3 个分类（常规/编辑器/AI），而不是 4 个或 5 个，这样分类清晰不冗余。
44. 作为一名用户，我希望在常规分类切换 UI 模式（浅色/深色/跟随系统）、显示隐藏文件、显示 Agent 面板、设置默认图片目录。
45. 作为一名用户，我希望在编辑器分类切换编辑模式（源码/分屏/所见即所得）、调整字体大小/行高/字体族、开关行号和软折行。
46. 作为一名用户，我希望在 AI 分类管理多个 Provider（新增/编辑/删除），并能为每个 Provider 填写名称/类型/Base URL/Model/API Key。
47. 作为一名用户，我希望在 AI 分类点击"测试连接"按钮验证 Provider 配置是否可用，并看到"上次测试：成功/失败"状态指示。
48. 作为一名用户，我希望删除 Provider 时弹出二次确认对话框，这样不会误删含 API Key 的配置。
49. 作为一名用户，我希望在 AI 分类底部看到一个折叠的"高级参数"区域，含 Agent 循环轮数上限/单次请求 token 上限/累计 token 软上限/propose_replace 二次确认阈值，这样高级用户可调参。
50. 作为一名用户，我希望切换编辑模式后不弹"需重启生效"提示，因为 0.3.0 的三种模式是运行时切换。

## Implementation Decisions

### 议题簇 0：设计系统基础

- **引入 `lucide-vue-next`** 作为统一图标库，替换所有 emoji + 内联 SVG + naive-ui NIcon。详见 [ADR-0004](adr/0004-lucide-vue-next-as-unified-icon-library.md)。
- **保留 naive-ui**，通过 `NConfigProvider` + `themeOverrides` 把 naive-ui 的颜色/圆角/字体变量映射到 `--murasaki-*` token。保留 naive-ui 的可访问性/键盘导航/焦点管理等行为。详见 [ADR-0005](adr/0005-keep-naive-ui-with-theme-overrides.md)。
- **不引入 Tailwind**，保留 scoped CSS + `--murasaki-*` token 变量。设计页的 Tailwind 工具类作为"视觉规格参考"而非"代码模板"，翻译规则：`bg-primary/10` → `background: rgba(147, 51, 234, 0.1)`。详见 [ADR-0006](adr/0006-no-tailwind-keep-scoped-css.md)。
- **token 补全**（在 [theme.css](../src/styles/theme.css)）：字号 token（`--murasaki-text-xs/sm/base/lg/xl/2xl` = 12/13/14/16/20/24px）、阴影 token（`--murasaki-shadow-sm/md/lg/2`）、布局 token（`--murasaki-menubar-height` = 32px，仅设计参考用）、过渡 token（`--murasaki-transition-fast` = 120ms ease）。间距/字重/行高保留硬编码不 token 化。
- **硬编码颜色清理**：[CompareWindow.vue](../src/components/CompareWindow.vue) 的 16 处 `#e8e8e8/#fafafa/#24292e/#d4f4dd/#ffe0e0` 全部替换为 `--murasaki-*` token；[SearchPanel.vue](../src/components/SearchPanel.vue) 的黄绿色同理。

### 议题簇 1：布局骨架

- **保留 Tauri 原生菜单栏**，不实现设计页的 32px in-app menu bar。应用内 grid 从 `32px 36px 1fr 24px` 简化为 `36px 1fr 24px`。详见 [ADR-0007](adr/0007-keep-tauri-native-menu-bar.md)。
- **标签栏移除主题选择器 NSelect**，标签栏仅保留 TabBar + 新建按钮。markdown 主题切换通过 OS 原生菜单（[menu.rs](../src-tauri/src/commands/menu.rs) 已有）+ 设置窗口（未来）。
- **布局保留 flex**（不改 grid），视觉数值对齐 token（260px/36px/24px/380px）。
- **状态栏按 ux-panels 规范补全**：移除当前 chip 组件样式，改为 lucide 图标项 + 文本；补全 `check` + `text-state-success` "已保存"指示、`message-square` + 计数的孤立会话清理按钮、`bg-primary/10 text-primary rounded` + `sparkles` 的 provider chip；保留 Agent 运行指示器。设计页 main-editor 与 ux-panels 的状态栏规范冲突时以 ux-panels 为权威。

### 议题簇 2：反馈系统

统一模式：**全局 Pinia store + 单一 Teleport 容器 + Promise/数据驱动 API**，不依赖 naive-ui 的 NMessage/NDialog/NDropdown。

- **吐司系统**：`useToastStore` + `ToastContainer.vue`。6 变体（success/info/warning/error/progress/deleted）。栈位置右上角 `top-4 right-4`，宽度 320px。自动消失策略：success/info 3s，warning/error 5s，progress 持续到任务完成，deleted 持续到撤销或 10s。所有变体都有 `x` 关闭按钮（progress 除外）。每个吐司可选 `action`（如撤销、重试、查看），点击触发回调并关闭吐司。z-index 用 `z-10` 在 NModal 之上。
- **对话框系统**：`useDialogStore` + `DialogContainer.vue`。4 类型：`alert`（单按钮，信息/警告/错误变体）、`confirm`（双按钮，可选危险变体）、`prompt`（双按钮 + 输入框，可选 placeholder/默认值/校验）、`conflict`（三按钮：取消/重命名/覆盖，覆盖为危险变体）。按钮顺序严格对齐设计：取消在左，确认在右。Promise-based API 替换 36 处原生 `alert()/confirm()/prompt()`。栈管理：同时只显示一个对话框（模态栈）。Escape 键等同点取消。打开时聚焦默认按钮（取消），prompt 聚焦输入框。
- **右键菜单系统**：`useContextMenuStore` + `ContextMenuContainer.vue`。数据驱动 MenuItem 接口（含 label/icon/shortcut/action/disabled/danger/separator）。4 处右键菜单：TabBar（8 项 + 分隔符，对齐 [main-editor.html:553-580](../murasaki-ui-design/pages/main-editor.html#L553)）、Editor（剪切/复制/粘贴/全选 + 分隔符 + 查找替换/插入表格/链接/图片/粘贴为纯文本，对齐 [ux-popovers-toolbars.html:437-510](../murasaki-ui-design/pages/ux-popovers-toolbars.html#L437)）、Agent 消息（4 项：复制/复制 Markdown 源码/插入到编辑器/从当前消息重新生成，对齐 [ux-panels.html:950-1014](../murasaki-ui-design/pages/ux-panels.html#L950)）、TreeNode（重命名/剪切/复制/粘贴/删除/分隔符/在文件资源管理器中显示，替换现有 NDropdown）。栈管理：同时只显示一个右键菜单。关闭时机：点击菜单项/点击外部/Escape/滚动。边界检测：菜单超出视口时自动调整位置。

### 议题簇 3：状态展示

自建状态展示组件三兄弟，共享虚线边框容器（`border border-dashed border-border rounded-lg m-4`）与 props 模式，替换 naive-ui NEmpty/NSpin/NSkeleton。

- **EmptyState**：props 含 `icon`（lucide 图标，`w-12 h-12 text-muted-foreground/50`）、`title`（`text-base font-medium mt-3`）、`description`（`text-sm text-muted-foreground mt-1`）、`actionText`/`actionIcon`/`@action` 事件。替换 [FileTree.vue](../src/components/FileTree.vue)/[OutlinePanel.vue](../src/components/OutlinePanel.vue)/[SearchPanel.vue](../src/components/SearchPanel.vue)/AgentPanel 无会话态的 NEmpty。
- **ErrorState**：props 含 `icon`（默认 `alert-triangle` 黄色，可覆盖如 `file-x`/`search-x`）、`title`/`description`/`retryText`（默认"重试"）/`@retry` 事件。
- **Skeleton**：props 含 `lines`（默认 4 行，宽度递减 100%/90%/95%/70%）、`icon`（可选，用于列表项骨架）。骨架条用 `h-4 bg-muted rounded animate-pulse`。替换文件树加载、大纲加载、搜索进行中的 NSpin/NSkeleton。

### 议题簇 4：面板与侧栏视觉

### 议题簇 7：WYSIWYG 模式

- **技术路线：CodeMirror 6 内 WYSIWYG（Typora 路线）**。单编辑器实例，markdown 文本为唯一数据源，通过 ViewPlugin + Decoration 隐藏/显示语法标记。不引入 Tiptap/ProseMirror 作为第二编辑器。详见 [ADR-0008](adr/0008-wysiwyg-via-codemirror6-typora-approach.md)。
- **三种编辑模式**（共用同一 CodeMirror 实例）：
  - `source`：纯源码，无预览区（CodeMirror 6 占满编辑区）
  - `split`：分屏，源码 + 预览（CodeMirror 6 + PreviewPane，`splitRatio` 可调）—— 默认模式
  - `wysiwyg`：所见即所得（CodeMirror 6 + WYSIWYG ViewPlugin 隐藏语法标记，预览区隐藏）
- **模式切换全部运行时**（无需重启）：`source` ↔ `split` 运行时切换（仅显隐预览区 + 调整布局），`wysiwyg` ↔ 其他运行时切换（叠加/移除 WYSIWYG ViewPlugin）。修正 [CONTEXT.md](../CONTEXT.md) 旧约定"切换后需重启应用生效"。
- **WYSIWYG 光标行为**：光标在当前段（空行分隔的连续文本行）→ 所有标记可见（dim 灰色 `opacity: 0.4; font-size: 80%` + 缩小）+ 渲染样式保留；光标离开当前段 → 所有标记隐藏（`display: none` 或零宽替换）+ 渲染样式保留。
- **WYSIWYG 功能优先级**：
  - P0（必须）：行级语法标记隐藏 + 基础渲染（标题 H1-H6/粗体/斜体/删除线/行内代码/列表/引用/分隔线）
  - P1（应该）：块级元素 widget（代码块 Shiki 高亮/链接锚文本/图片渲染/表格对齐/数学公式 KaTeX/Mermaid SVG）
  - P2/P3（遗留后续版本）：YAML frontmatter 卡片 / emoji 短代码替换 / 脚注 / TOC / HTML 内联
- **与 Agent 提案的优先级**：Agent 提案 decoration（绿色 insert / 红色 strikethrough）优先级高于 WYSIWYG 隐藏 decoration。提案覆盖范围不隐藏语法标记（用户需看到原始 markdown 判断提案）。Agent 面板在三种模式都可见可用。
- **ViewPlugin 实现要点**：遍历 `@codemirror/lang-markdown` 语法树，对语法标记 token（HeaderMark/EmphasisMark/CodeMark/QuoteMark/ListMark/LinkMark 等）应用 Decoration。监听 `view.state.selection` 变化 + `view.docView` 变化（防抖 50ms）。大文档（>10000 行）的 ViewPlugin 遍历需增量更新（仅重计算可见区域 ± buffer）。

### 议题簇 8：设置界面

- **设置窗口改为 Tauri 多窗口形态**：在 `tauri.conf.json` 的 windows 数组新增 settings 窗口配置（label: `settings`，初始隐藏）。新增 `settings.html` 入口。通过 Tauri 命令创建/显示设置窗口。设置变更通过 Tauri event 通知主窗口应用副作用。详见 [ADR-0009](adr/0009-settings-window-as-tauri-multi-window.md)。
- **3 个分类**（无主题/快捷键）：
  - **常规**：UI 模式（浅色/深色/跟随系统）/ 显示隐藏文件 / 显示 Agent 面板 / 默认图片目录
  - **编辑器**：编辑模式（source/split/wysiwyg）/ 字体大小 / 行高 / 字体族 / 显示行号 / 软折行
  - **AI**：Provider 列表 + 编辑表单（名称/类型/Base URL/Model/API Key）/ 默认 Provider / 高级参数折叠区
- **保存模型：显式 Save**：footer 含「恢复默认 / 保存」两个按钮。改动暂存在 draft，点保存才落盘 + 触发副作用。点恢复默认重置当前分类。关闭未保存弹确认（保存/不保存/取消，与 tab 关闭未保存逻辑一致）。副作用统一触发（一次 save 把所有改动一次性应用，通过 Tauri event 通知主窗口）。
- **AI 分类补充决策**：
  - **Provider 类型**：仅支持「OpenAI 兼容」，不支持 Azure OpenAI（UX 设计页需移除该选项，0.3.0 不实现）。
  - **测试连接**：0.3.0 实现。`useAiProvidersStore` 新增 `testProvider(id)` 方法，向后端 `GET /v1/models` 发请求验证连通性，返回成功/失败 + 错误信息。状态指示器显示上次测试结果（存 localStorage）。
  - **Provider 删除二次确认**：点击删除按钮弹 confirm 对话框（"确定删除 Provider {name}？"），确认后删除。
- **0.3.0 不做的新功能设置项**：自动保存间隔 / 最小化到托盘 / 界面语言 / 启动时打开上次工作区。Mermaid/KaTeX/任务列表渲染默认开启不暴露设置项。

## Testing Decisions

### 测试哲学

- **只测外部行为，不测实现细节**。测试不应在重构时频繁失败。
- **优先复用现有测试缝隙**，不轻易新增缝隙。理想缝隙数量是 1（E2E）。
- **测试针对功能，不针对编辑模式**。三种模式共用同一 CM6 实例，核心功能等价，不为每种模式独立设计 spec。

### 现有测试缝隙（复用）

1. **前端单元测试**（`npm test`，Vitest）—— composables / stores / utils
2. **Rust 测试**（`npm run test:rust`，cargo test）—— Tauri commands
3. **E2E 测试**（`npm run test:e2e`，webdriverio + tauri-driver）—— 完整用户流程，复用 [e2e/helpers/](../e2e/helpers/) 的 driver/fixtures 基础设施（详见 [ADR-0003](adr/0003-agent-e2e-full-stack-testing.md)）

### 议题簇 7 测试缝隙细分

- **7a ViewPlugin decoration 计算**：前端单元测试。提取 ViewPlugin 的 decoration 计算为纯函数，断言给定 markdown 文本 + 光标位置 → 预期 decoration 集合。
- **7b 光标行为**（标记显隐）：E2E。模拟光标移动断言视觉。
- **7c 块级 widget 渲染**：E2E。断言 widget 渲染。
- **7d 模式切换**（source↔split↔wysiwyg）：E2E。验证切换后编辑器状态正确（内容不丢失、光标位置合理）。
- **7e Agent 提案在三种模式下的兼容性**：E2E（扩展现有 [agent-proposals.spec.ts](../e2e/specs/agent-proposals.spec.ts)）。验证在三种模式下都能渲染提案。

### 新增测试缝隙

- **CodeMirror 6 ViewPlugin 单元测试**：WYSIWYG 的 decoration 逻辑（语法标记识别 + 光标位置判断 + decoration 生成）提取为纯函数用单元测试覆盖。这是议题簇 7 的核心，E2E 难以断言具体的 decoration 状态。

## Out of Scope

0.3.0 明确不做以下内容（遗留后续版本）：

- **WYSIWYG P2/P3 功能**：YAML frontmatter 卡片 / emoji 短代码替换 / 脚注 / TOC `[toc]` 自动生成 / HTML 内联渲染
- **设置界面的快捷键自定义分类**：0.3.0 不做快捷键自定义 UI
- **设置界面的主题分类**：markdown 主题通过 OS 原生菜单切换，不放入设置
- **新功能设置项**：自动保存间隔 / 最小化到托盘 / 界面语言（i18n 框架）/ 启动时打开上次工作区
- **Azure OpenAI 支持**：Provider 类型仅支持「OpenAI 兼容」
- **naive-ui 完全移除**：保留 naive-ui 作为复杂组件来源
- **Tailwind 引入**：保留 scoped CSS
- **应用内 in-app menu bar**：保留 Tauri 原生菜单栏
- **WYSIWYG 模式下 Agent 提案的 Tiptap 自定义节点渲染**：0.3.0 用 CodeMirror 6 内 WYSIWYG，Agent 提案原生兼容，无需此适配
