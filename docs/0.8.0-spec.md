# Murasaki 0.8.0 — 中文符号自动转 Markdown 记号 Spec

## Problem Statement

中文用户在中文输入法下撰写 Markdown 时，行首的结构记号（`>` `[` `]` ` ``` ` `-` `#` `*` `~`）要么打不出全角形式，要么需要频繁切换中英输入法，打断写作流。例如输入一个引用块要先切英文敲 `>`，再切回中文继续打字。

现有产品对此无任何缓解：所有行首结构记号都必须手打 ASCII 字符，中文输入法下无法用全角符号替代。

## Solution

0.8.0 引入「中文符号转 Markdown 记号」选项：用户在**行首**（允许前导空格）输入连续的全角/中文符号后**加空格**，编辑器将整串一次性自动转换为对应的 markdown 结构记号，无需切换中英输入法。总开关默认开启，可在「系统设置 → 编辑器」关闭，映射表在该处只读展示。

### 映射表（固定内置）

| 输入（行首） | 转换后 | 含义 | 备注 |
|---|---|---|---|
| `》` | `>` | 引用 | `》》` → `>>` 嵌套引用 |
| `···` | ` ``` ` | 围栏代码 | 三连间隔号 |
| `【】` | `[]` | 方括号 | 任务列表 / 链接 |
| `·` | `-` | 无序列表 | |
| `＊` ／ `－` | `*` ／ `-` | 无序列表 | |
| `＃` | `#` | 标题 | `＃＃` → `##` |
| `～` | `~` | 删除线 | |
| `＊＊＊` | `***` | 分割线 | |

### 转换行为

- **触发**：行首（允许前导空格）输入连续的可转换全角符号后按下空格；按下空格时一次性转换整串。
- **整串转换**：连续符号按映射表整体转换（多字符规则优先于单字符，如 `···` → ` ``` ` 而非 `- - -`）。
- **保留空格**：转换后保留触发空格（`》` + 空格 → `> `，标准 markdown 结构）。
- **嵌套**：连续同类结构符号按数量转换（`》》` → `>>`、`＃＃` → `##`）。
- **撤销**：符号输入 + 空格 + 转换合并为**一个撤销步**，`Ctrl+Z` 一次还原为原始全角符号。
- **排除代码范围**：已存在的围栏代码 / 内联代码范围内不转换。
- **文件类型限定**：仅 `.md` / `.markdown` 文件生效，非 markdown 文件不转换。
- **模式**：源码模式与 WYSIWYG 模式均生效（CM6 输入层统一实现，一处生效）。

### 设置项

- 字段：`fullwidthToMarkdown`（布尔，默认 `true`）。
- 位置：「系统设置 → 编辑器」分类，`toggle-switch` 开关 + 只读映射表（中文符号 | 转换后）。
- 文案（zh/en 双语）：label「中文符号自动转 Markdown 记号」。

## User Stories

### 议题簇 0：设置项

1. 作为一名中文用户，我希望在「设置 → 编辑器」看到一个开关控制该功能，并默认开启，这样无需额外配置即可使用。
2. 作为一名中文用户，我希望设置里能看到一张只读映射表（中文符号 | 转换结果），这样我不用猜哪些符号会被转换。
3. 作为一名开发者，我希望该设置项遵循既有 settings 接线（types → settingsLogic 分类字段 → EditorPanel → updateSettings → `settings://saved`），这样行为与其他设置项一致（dirty 判断 / 恢复默认 / 关闭确认）。

### 议题簇 1：转换核心

4. 作为一名中文用户，我在行首输入 `》` 加空格，期望立即变成 `> `（引用块）。
5. 作为一名中文用户，我在行首输入 `》》` 加空格，期望变成 `>>`（嵌套引用）。
6. 作为一名中文用户，我在行首输入 `···` 加空格，期望变成 ` ``` `（围栏代码）。
7. 作为一名中文用户，我在行首输入 `【】` 加空格，期望变成 `[]`（方括号）。
8. 作为一名中文用户，我在行首输入 `·` / `＊` / `－` 加空格，期望变成 `-` / `*` / `-`（无序列表）。
9. 作为一名中文用户，我在行首输入 `＃` 加空格，期望变成 `#`（标题），`＃＃` 变 `##`。
10. 作为一名中文用户，我在行首输入 `～` / `＊＊＊` 加空格，期望变成 `~` / `***`。
11. 作为一名中文用户，我在正文中间输入 `》`（非行首）加空格，期望**不转换**（不影响中文正文输入）。
12. 作为一名中文用户，我在行首输入 `》` 但后续**不按空格**（如直接按 Enter 或继续打字），期望不转换。
13. 作为一名用户，转换后按 `Ctrl+Z`，期望一步还原为原始全角符号（`> ` → `》`）。
14. 作为一名用户，我在代码块内部输入 `》` 加空格，期望**不转换**。
15. 作为一名用户，我在非 markdown 文件（`.txt`）中行首输入 `》` 加空格，期望**不转换**。
16. 作为一名用户，我在 WYSIWYG 模式下用同样方式输入，期望同样转换（与源码模式一致）。
17. 作为一名用户，我在设置里关闭开关后，行首输入全角符号加空格，期望**不再转换**。

## Implementation Decisions

### 议题簇 0：设置项

- `SettingsState` 增加 `fullwidthToMarkdown: boolean`，`DEFAULT_SETTINGS` 默认 `true`（见 [types.ts](../src/types.ts)）。
- `settingsLogic.ts` 的编辑器分类字段列表加入 `fullwidthToMarkdown`，纳入 dirty 判断 / 恢复默认。
- `EditorPanel.vue` 增加 `toggle-switch` 开关 + 只读映射表（复用 `GeneralPanel` 的 checkbox/toggle 模式）。
- i18n：`settings.json`（zh/en）增加 label + description 文案。

### 议题簇 1：转换核心

- 新增映射表常量（单一出处），供转换扩展与设置面板只读展示共用。
- 实现为 CM6 输入层扩展（仿 `emojiSourceReplacer` 的 ViewPlugin/state effect 模式，见 [wysiwygPlugin.ts](../src/editor/wysiwyg/wysiwygPlugin.ts#L779-L855)），监听空格输入：
  - 校验当前是否 markdown 文件（编辑器上下文提供）。
  - 校验光标前是否为行首（允许前导空格）。
  - 提取行首连续可转换符号串，按映射表整串转换（多字符规则优先）。
  - 排除代码范围（复用编辑器语法树/状态判断，与 emoji 替换一致）。
  - 通过单个 `view.dispatch` 提交转换 + 空格，合并为一个 undo 步。
- 设置关闭时不注册该扩展；开关状态经 Pinia `persistence.settings` 响应式生效。

### 议题簇 2：测试

- 转换逻辑抽为纯函数（输入符号串 + 位置 → 输出），便于单测。
- 单测覆盖：单字符映射、多字符规则（`···`/`＊＊＊`）、嵌套（`》》`/`＃＃`）、非行首不转换、行首无空格不触发、代码范围排除、非 md 文件不转换、关闭开关不转换。

## Non-Goals

- 不支持任意位置（正文中）的全角→半角替换。
- 不支持用户自定义映射表（固定内置，设置仅只读展示）。
- 不改变既有中文正文输入行为（默认开启但仅在行首 + 空格时触发，不打断正文 IME 输入）。
