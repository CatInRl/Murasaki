# ADR 0001: 草稿恢复 + mtime 冲突解决

## 状态

已接受

## 背景

应用支持多标签页，标签页状态在应用关闭时持久化、下次启动恢复（见 CONTEXT.md "标签页"）。这带来一个问题：未保存的修改怎么办？

两种粒度：

- **A. 只恢复打开过的文件列表** —— 内容从磁盘读，未保存修改丢失。
- **B. 恢复文件列表 + 未保存草稿** —— 即使磁盘没保存，草稿也能恢复。VS Code 采用此模式。

## 决策

采用 B，并附加明确的冲突解决规则。

### 规则

1. 每个 tab 关闭或应用退出时，若文件有未保存修改，草稿写入 app data 目录。
2. 文件正常保存到磁盘后，对应草稿立即删除。
3. 下次启动恢复 tab 时：
   - 比较磁盘文件的 mtime 与 tab 记录的"上次已知 mtime"。
   - **一致** → 用草稿内容恢复（保留未保存修改）。
   - **不一致**（文件被外部修改过）→ 弹窗提示"文件已被外部修改，是否加载磁盘版本 / 保留草稿"，由用户选择。
4. 草稿不保留历史版本，只保留最后一份。

## 备选方案

**A. 只恢复文件列表** —— 实现简单，但丢未保存修改，与"管理工具"定位不符。用户在长会话中误关应用会丢失大量工作。

## 后果

**正面**
- 未保存修改不丢，符合现代编辑器预期。
- 外部修改冲突有明确处理路径，不静默覆盖。

**负面**
- 实现复杂度上升：需草稿读写、mtime 比对、冲突对话框。
- app data 目录会残留草稿文件（仅当用户主动放弃保存时），需考虑清理策略（暂不实现，未来可加"启动时清理 30 天前草稿"）。
- 草稿格式一旦确定，未来迁移需考虑兼容。
